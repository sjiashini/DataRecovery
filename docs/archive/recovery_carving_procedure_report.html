Recovery & Carving — Step-by-Step

Pendrive imaging with ddrescue and PhotoRec file carving through the Video Studio recovery tab (WSL2 + usbipd)

The Prompt

"Ok Give me Proper Step Step by Procedure for Recovery and Carving"

Step 0 — Prerequisites (all already true on this machine)

Check Status
usbipd-win 5.3.0 installed, 4-9 already bound
WSL distro Ubuntu registered, default
ddrescue / photorec / testdisk installed at /usr/bin/
raw device read permission aditss is in disk group — no sudo needed
free space on C: 64.7 GB

Step 1 — Start the app

start_studio.bat, or python video_studio_backend.py --open-browser. Always open the served page at http://127.0.0.1:8080/ — never the .html file, or every API call fails with a token error.

Bash 
python video_studio_backend.py --open-browser

Step 2 — Plug in and stop touching the drive

Every write to it destroys recoverable data. Don't let Windows format or mount it.

Step 3 — Detect Drives

Open 💿💾 CD/DVD & Pen Drive Recovery → click 🔄 Detect Drives. Two outcomes:

  • ✔ 1 drive(s) detected naming /dev/sde → go to Step 5.
  • A 🔗 4-9 button appears → the drive is visible to Windows but not in WSL.

Step 4 — Share (only if 🔗 appeared)

Click 🔗 4-9. Approve the UAC prompt if one shows — it won't for this port, since bind persists across reboots. The app binds, waits for WSL, attaches, and polls lsblk until the disk is genuinely enumerable. Then Detect Drives again.

Step 5 — Configure

  • Output Raw Image Path: C:\PendriveRecovery\<name>.img. Never a path on the drive being recovered.
  • Sector Size: Auto — it correctly detected 512 B for your drive.
  • Mode: Normal Recovery first. Only switch to Aggressive if the ddrescue log shows bad sectors.
  • Carve checkbox: leave ticked for a one-shot run; untick to image now and carve later via Step 2.
  • File types: untick 🌐 All file types and tick only what you need. Scanning for every signature on a 15.9 GB image is much slower and produces far more junk.
Plain Text 
C:\PendriveRecovery\pendrive_backup.img

Step 6 — Run

Click 🚀 Run Full Recovery (Image + Carve). It runs ddrescue → TestDisk → PhotoRec and streams progress. ⏹️ Cancel stops it. Keep the app open.

Critical: the .img.log mapfile lets ddrescue resume — if a run dies, re-run with the same output path and it continues where it stopped. Don't delete .img.log until you're done.

Step 7 — Optional: original filenames

PhotoRec recovers content but not names. If the filesystem is merely corrupted rather than wiped, click 🛠️ Open TestDisk (original names) — that can restore real filenames and folders.

Step 8 — Release the drive

Wait for "Recovery completed", then click ⏏ 4-9 under the device dropdown. No cooling period — the pipeline never writes to the pen drive. Until you click it, the drive stays hidden from This PC by design.

Step 9 — Verify before wiping anything

C:\PendriveRecovery\<timestamp>\ holds pendrive_backup.img + carved.1\, .2\… Open a few recovered files first. Only then reformat the drive.

One space warning

Your last run left 18 GB in 2026-10-21_18-11-19 and 15 GB in the older VS-Test-2026-10-20_1958 — 33 GB of the 64.7 GB free. A repeat run needs roughly 30 GB, which fits but leaves little margin. Delete the VS-Test-* folder or point output at D:\PendriveRecovery (also an allowed root, 73 GB free).

Right now the drive is attached to WSL from my testing, so it won't appear in This PC until you click ⏏ — or just start at Step 3, since it's already shared and ready.

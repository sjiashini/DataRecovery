In practice

Three phases

1. Automation and housekeeping

About 4.1 after 1–2 weeks part-time

  • CI, build gate, releases
  • Delete the legacy routes
  • Free-space check
  • Show storage failures
  • Retention and migrations
  • Structured logs

2. Frontend and hardening

About 4.5 after 3–5 weeks

  • Split the page and add browser tests
  • Cookie auth and nonce CSP
  • API v1 with proper status codes
  • Diagnostics export
  • Simulated failing disk
  • A real-media run

3. Consolidation

5.0 after 4–8 weeks

  • One UI
  • One execution model
  • Support matrix
  • Benchmarks
  • Coverage and type-check gates
  • Signed releases if you share the exe
Honest advice

Where to stop

  • Phase 1 is the best value. It's mostly small, safe changes, and CI protects everything after it.
  • Stopping at about 4.5 is reasonable for a personal tool. The last half point is the most expensive: rewriting the frontend, picking one UI, and unifying the concurrency model, for a one-user app.
  • 5/5 doesn't mean perfect. At this scale it means "nothing material left to improve". Even then, the real test of a recovery tool is a failing disc, which is why the real-media run is in phase 2, not last.

I can start on phase 1 now. The free-space check and deleting the legacy routes are the quickest wins.
